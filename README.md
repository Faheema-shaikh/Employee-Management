# Employee-Management
A Spring Boot REST API for managing employee records using a layered architecture. The application supports creating, retrieving, updating, and deleting employees, with request validation, DTO-based responses, centralized exception handling, PostgreSQL persistence, and Swagger UI documentation.
Features
- Create, retrieve, update, and delete employee records
- Layered structure: Controller, Service, Repository, Entity, DTO, and Exception Handler
- Request validation using Jakarta Bean Validation
- Request and response DTOs; API responses do not expose JPA entities
- Centralized error responses using @RestControllerAdvice
- Duplicate email checks
- PostgreSQL database integration with Spring Data JPA / Hibernate
- Transaction management in the service layer
- Swagger UI / OpenAPI documentation
Tech Stack
- Java (use the version configured in pom.xml)
- Spring Boot
- Spring Web
- Spring Data JPA / Hibernate
- PostgreSQL
- Jakarta Bean Validation
- Springdoc OpenAPI / Swagger UI
- Maven

Getting Started
1. Clone the repository
Replace the placeholder with your GitHub repository URL:
git clone https://github.com/Faheema-shaikh/Employee-Management.git)
cd Employee-Management
2. Create or select a PostgreSQL database
This project is currently configured to use the local PostgreSQL database named postgres on port 5432.

You can keep using that database for this assessment, or create a dedicated database and update DB_URL accordingly. The application uses:
jdbc:postgresql://localhost:5432/postgres
Hibernate is configured with spring.jpa.hibernate.ddl-auto=update, so it updates the schema based on the JPA entities when the application starts. For a production system, use managed database migrations instead.
3. Configure database credentials
The application reads its database settings from environment variables, with defaults for the URL and username. Set the password locally; do not commit real credentials to GitHub.

Windows PowerShell:
$env:DB_URL="jdbc:postgresql://localhost:5432/postgres"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="your_local_postgres_password"
Windows Command Prompt:
set DB_URL=jdbc:postgresql://localhost:5432/postgres
set DB_USERNAME=postgres
set DB_PASSWORD=your_local_postgres_password
Alternatively, configure these environment variables in IntelliJ IDEA under Run → Edit Configurations → Environment variables for the Spring Boot run configuration.

Ensure application.properties contains:
spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5432/postgres}
spring.datasource.username=${DB_USERNAME:postgres}
spring.datasource.password=${DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=update
Do not commit your actual database password. If a real password was previously pushed to a public repository, rotate it.
4. Run the application
From the project root, run:
mvn spring-boot:run
Or run the main Spring Boot application class from IntelliJ IDEA.

The API will normally be available at:
http://localhost:8080
API Documentation
Once the application is running, open Swagger UI:
- Swagger UI: http://localhost:8080/swagger-ui/index.html
- OpenAPI JSON: http://localhost:8080/v3/api-docs
Swagger UI lets you inspect the endpoints and try requests directly from the browser.
API Endpoints
The base path is /employee.
Method	Endpoint	Description	Typical success status
POST	/employee	Create an employee	201 Created
GET	/employee	Retrieve all employees	200 OK
GET	/employee/{id}	Retrieve an employee by ID	200 OK
PUT	/employee/{id}	Update an employee	200 OK
DELETE	/employee/{id}	Delete an employee	204 No Content


Employee fields
The employee request contains the following fields:
- firstName
- lastName
- email
- phoneNumber
- department
- designation
- salary
- status
The id is generated by the application/database.
Sample request: Create an employee
POST /employee
Content-Type: application/json
{
  "firstName": "Aisha",
  "lastName": "Khan",
  "email": "aisha.khan@example.com",
  "phoneNumber": "9876543210",
  "department": "Engineering",
  "designation": "Software Developer",
  "salary": 60000.0,
  "status": true
}
Sample success response
The API returns an employee response DTO rather than the JPA entity. Example:
{
  "id": 1,
  "firstName": "Aisha",
  "lastName": "Khan",
  "email": "aisha.khan@example.com",
  "phoneNumber": "9876543210",
  "department": "Engineering",
  "designation": "Software Developer",
  "salary": 60000.0,
  "status": true
}
The generated id and returned values depend on the data saved in your database.
Validation and Error Handling
The API validates incoming request data and uses a centralized exception handler to return structured error responses.

Expected error scenarios include:
- 400 Bad Request — invalid request data or JSON
- 404 Not Found — employee ID does not exist
- 409 Conflict — duplicate email or a database integrity conflict
- 500 Internal Server Error — unexpected server-side error
An error response may look like this (the exact values depend on the error):
{
  "timestamp": "2026-10-23T10:00:00Z",
  "status": 404,
  "error": "Not Found",
  "message": "Employee not found with id: 99",
  "path": "/employee/99",
  "validationErrors": {}
}
For validation failures, validationErrors can contain field-specific messages.

Configuration Notes
